# OIDC hardening
Production requires an HTTPS issuer, explicit audience, asymmetric algorithm allowlist, bounded skew/token size/lifetime, subject, expiry and issued-at. `nbf`, authorised party, token type, scopes, critical headers and service `jti` are validated. Discovery must report the exact issuer; JWKS URLs and redirects retain scheme, host, and effective port. Responses and key counts are bounded; duplicate/encryption keys are rejected. Unknown keys receive one refresh and negative caching. Rotation accepts a newly trusted signing key after controlled refresh and never uses stale material for an unknown key.
